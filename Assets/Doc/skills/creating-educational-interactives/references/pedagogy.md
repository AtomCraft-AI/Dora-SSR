# Shared Pedagogy Rules

## 1. Interaction = Cognition

Every major interaction must correspond to a useful cognitive action:

| Learning intention | Prefer |
|---|---|
| notice a relationship | manipulate a variable and compare outcomes |
| understand a process | step, pause, scrub, or reorder the process |
| build a model | assemble components and test behavior |
| interpret evidence | inspect, classify, connect, cite, or rank evidence |
| learn a procedure | perform the procedure with recoverable mistakes |
| practice language | make meaning in a realistic communicative situation |
| learn programming | construct, execute, trace, debug, and optimize code |
| create | make an artifact under meaningful constraints and reflect on choices |

A quiz may support these actions, but should not replace them.

## 2. Productive Failure

Design mistakes that are safe, visible, and informative. Prefer:

1. show what happened;
2. point to the relevant state or step;
3. offer a hint tied to the concept;
4. let the learner retry;
5. reveal a worked explanation only after repeated difficulty or explicit request.

## 3. Progressive Disclosure

Do not show every control at once. Introduce variables, tools, and concepts as the learner needs them. Teacher mode may expose an “advanced controls” or “free exploration” panel.

## 4. Compare Before Explain

When teaching relationships, first create contrast: two trials, two texts, two maps, two strategies, or before/after states. Ask the learner to notice a difference, then name or explain the concept.

## 5. Multiple Representations

When useful, connect at least two representations: object + data table, motion + graph, equation + graph, map + timeline, sentence + semantic intent, source + claim, code + execution trace.

## 6. Age Fit

Primary: short instructions, concrete objects, limited simultaneous variables, immediate feedback.

Junior high: guided inquiry, explicit comparisons, emerging abstraction, evidence-based explanations.

Senior high: multi-variable reasoning, formal models, trade-offs, interpretation, open-ended investigation.

## 7. Evidence of Learning

Completion should mean more than reaching an endpoint. Good evidence includes:

- producing a stable experimental result and explaining it;
- solving a novel case with the same principle;
- debugging a faulty model or program;
- selecting evidence that supports a claim;
- creating a valid artifact under constraints;
- improving a solution and explaining the improvement.
