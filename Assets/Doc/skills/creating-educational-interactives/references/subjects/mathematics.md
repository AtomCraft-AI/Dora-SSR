# Mathematics

## Learning Actions

Manipulate, construct, transform, estimate, compare, conjecture, prove/explain, and solve a new case.

## Strong Patterns

- [Interactive visualization](@agent-skill/builtin/creating-educational-interactives/patterns/interactive-visualization.md): functions, geometry, fractions, probability
- [Inquiry learning](@agent-skill/builtin/creating-educational-interactives/patterns/inquiry-learning.md): conjecture from cases
- [Creation studio](@agent-skill/builtin/creating-educational-interactives/patterns/creation-studio.md): geometric constructions, data displays, models

## Knowledge Model

Represent exact mathematical relationships, not decorative animations. Couple symbolic and visual representations when useful: equation ↔ graph, fraction ↔ area/number line, geometry ↔ measurements.

## Design Rules

- Every draggable parameter must update all dependent values immediately.
- Preserve scale, units, domain restrictions, and sign conventions.
- Use counterexamples to challenge overgeneralization.
- For probability, expose repeated trials and frequency convergence without claiming finite trials “prove” probability.

## Teacher Mode

Add revealable construction lines, coordinates, algebraic steps, and compare-two-cases controls.

## Student Mode

Ask learners to make a target shape/value/graph first, then explain which parameter mattered.

## Avoid

Answer-speed arcade games as the main learning activity, misleading graph scales, or accepting numerically close answers when exact structure matters without explanation.
